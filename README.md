# Foly Status

Status page for the Foly services, powered by [Upptime](https://upptime.js.org) — GitHub
Actions probe each endpoint every five minutes, commit the results to this repository and
publish the page to GitHub Pages.

Live at **https://status.foly.app**.

## Services monitored

| Service | Probe | Down when |
| --- | --- | --- |
| Foly API | `https://api.foly.app/healthz` | non-200, or the body stops saying `"status":"healthy"` |
| Foly App | `https://app.foly.app/en-US/` | non-200 |
| Foly Marketing | `https://foly.app` | non-200 |

## How it works

- [`.upptimerc.yml`](.upptimerc.yml) is the only file to edit: the sites, the page's
  name/theme/navigation and the CNAME. The workflows under `.github/workflows/` come from
  the Upptime template and are regenerated by the **Setup CI** workflow whenever the config
  changes — never edit them by hand.
- `history/`, `api/` and `graphs/` are written by the workflows (uptime history, response
  times, the JSON the page reads). Commits from Upptime carry `[skip ci]`.
- The page is built from the `gh-pages` branch; DNS is a Cloudflare CNAME `status` →
  `foly-investment.github.io` (DNS only, not proxied).
- Outages open a GitHub issue assigned to the maintainer and close it on recovery.

The workflows authenticate with a `GH_PAT` repository secret (a personal access token
with `repo` and `workflow` scopes) so they can push results and open issues.
